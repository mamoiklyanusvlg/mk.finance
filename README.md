# «Мамой клянусь — финансы»: API и приложение

## Что в папке

| Файл | Что это |
|---|---|
| `apps-script/app_api.gs` | API для проекта Apps Script «Saby выгрузка». Читает и пишет файл месяца. |
| `apps-script/app_router.gs` | `doGet` и `doPost`. Нужен, только если в проекте их ещё нет. |
| `index.html` | Приложение: iPhone (нижнее меню) и Mac (боковое меню, от 900 px). |
| `config.js` | Адрес API и Client ID для входа через Google. |
| `demo.js` (не в репозитории) | Демо-данные: если `config.js` пустой, приложение открывается на них. |
| `manifest.webmanifest`, `sw.js` | Установка на экран «Домой». Иконки делаются на шаге 3. |

## Как устроен API

Один адрес веб-приложения, запросы `POST` с JSON `{action, session, month, …}`.
`month` — `current` или `prev` (файлы из свойств `MF_CURRENT_ID` / `MF_PREV_ID`).

**Вход.** Приложение получает у Google подтверждение почты (Sign in with Google),
API проверяет его и выдаёт свою сессию на 60 дней. На каждом запросе API заново
смотрит список пользователей, поэтому удалённый пользователь теряет доступ сразу.
Список пользователей и ролей хранится в свойствах скрипта (`APP_USERS`) и правится
из приложения на экране «Пользователи и роли».

**Роли.**

| | Владелец | Управляющий | Сотрудник |
|---|---|---|---|
| Сводка | смотрит | смотрит | — |
| Прибыль (отчёт о прибыли) | смотрит | — | — |
| Выручка, Купер | меняет | смотрит | — |
| Расходы и чеки | меняет | меняет | только свои |
| Постоянные и налоги | меняет | меняет | — |
| Смены | меняет | меняет | свою, за сегодня и вчера |
| ЗП и выплаты | меняет | меняет | свои, только смотрит |
| Деньги и корректировки | меняет | смотрит | — |
| Пользователи и роли | меняет | — | — |

**Действия.** Чтение: `load` (всё, что разрешено роли, одним запросом), `summary`,
`revenue`, `expenses`, `fixed`, `payroll`, `cashflow`, `users`.
Запись: `setCooper`, `addExpense`, `deleteExpense`, `payFixed`, `addFixedItem`,
`setShift`, `addPayout`, `addCorrection`, `saveUser`, `removeUser`.

**Куда пишет.** Только в ячейки, которые сейчас заполняются руками. Формулы не трогает.

| Действие | Лист и ячейки |
|---|---|
| Расход | «Расходы», первая свободная строка в A–F. В комментарий добавляется «внёс: Имя». |
| Удаление расхода | «Расходы», строки ниже сдвигаются вверх только в A–F (сводка справа не двигается). Перед удалением API сверяет дату, сумму и категорию. |
| Оплата постоянной статьи | «Постоянные»: неоплаченная статья заполняется в своей строке, повторная оплата идёт новой строкой. |
| Новая статья | «Постоянные», новая строка без даты и суммы. |
| Смена | «ЗП», галочка «Смена» нужного сотрудника в строке дня. Начисление считает формула. |
| Выплата ЗП | «ЗП», блок «Выплаты», первая свободная строка. |
| Купер | «Выручка», колонка «Купер» в строке дня. |
| Корректировка | «Кэшфлоу», колонки «Корректировка» (касса F, счёт M) в строке дня: сумма прибавляется к тому, что там уже есть, а описание дописывается в примечание к ячейке. Сверка остатка считает «факт минус учёт» на конец выбранного дня. |

Все записи идут под блокировкой (`LockService`), чтобы два человека не записали в одну строку.
Дата проверяется: в файл октября нельзя записать ноябрьский расход.

«Деньги сейчас» берутся из строки «Кэшфлоу» за сегодня, прогноз — из последнего дня
месяца. Будущие поступления (Яндекс, Купер, эквайринг) показываются отдельно.

## Как подключить (шаги 1–2)

1. **Client ID для входа через Google.** Раздел в консоли теперь называется «Google Auth Platform».
   - [Создать проект](https://console.cloud.google.com/projectcreate): имя «МК финансы» → «Создать». Дальше проверять, что он выбран вверху слева.
   - [Google Auth Platform](https://console.cloud.google.com/auth/overview) → «Начать» (Get started): название
     приложения, почта поддержки, аудитория «Внешние» (External), контактная почта → «Создать».
   - Публиковать не нужно, оставить режим «Testing». Слева «Аудитория» (Audience) → «Тестовые пользователи»
     (Test users) → добавить Google-почты всех, кто будет входить (до 100). Нового сотрудника добавлять
     и сюда, и в приложение. Ограничения тестового режима приложению не мешают: Google проверяет почту только при входе.
   - Слева [«Клиенты»](https://console.cloud.google.com/auth/clients) → «Создать клиента» → тип «Веб-приложение»
     → в «Разрешённые источники JavaScript» добавить адрес приложения (например `https://<логин>.github.io`;
     его можно вписать и позже) → «Создать» → скопировать Client ID (`…apps.googleusercontent.com`).
2. **Код в Apps Script.** В проекте «Saby выгрузка» создать файл `app_api` и вставить `app_api.gs`.
   Если в проекте **нет** функций `doGet`/`doPost`, добавить и `app_router.gs`.
   Если `doPost` уже есть (например, для Telegram-бота), добавить первой строкой внутри него:
   ```js
   try { if (JSON.parse(e.postData.contents).action) return appDoPost_(e); } catch (err) {}
   ```
3. Вверху `app_api.gs` заполнить `APP_SETUP` (почта владельца и Client ID) и один раз
   запустить функцию `appSetup` из редактора.
4. **Развернуть** → «Новое развёртывание» → «Веб-приложение»: запуск от имени «Я»,
   доступ «Все». Адрес сам по себе ничего не открывает: без входа через Google API отвечает
   «Нужно войти». Существующие развёртывания (бот и т.п.) не меняются.
5. В `config.js` вписать адрес развёртывания (`…/exec`) и Client ID.
6. Приложение публикуется через GitHub Pages из корня ветки `main` и добавить остальных пользователей
   в приложении: «Пользователи и роли» → «Добавить по Google-почте».

Выйти на всех устройствах сразу: запустить `appResetSessions`.

## Чеки по фото

В «Новом расходе» фото распознаётся тем же Claude, что и в Telegram-боте (`rcRecognize_` из `receipts_bot.gs`):
сумма, дата, магазин и категория заполняются сами, их можно поправить перед сохранением.
Фото сохраняется в ту же папку «Чеки и накладные/ГГГГ-ММ», ссылка попадает в комментарий.
